Semantic review of `review/semantic.cpp`, compiled with
`clang++ -std=c++20 -Wall -Wextra -Werror -fsyntax-only`:

- `borrowed_callback`, lines 8–10: the returned closure borrows local state destroyed
  on return; invoking it uses a dangling reference. Capture an owned value if snapshot
  semantics are intended, or define an external owner's lifetime explicitly.
- `swapped_id`, lines 5–6 and 14: UserId and AssetId are aliases of the same type;
  the compiler accepts an asset as a user. Use distinct validated wrappers where
  that domain distinction is required; aliases cannot enforce it.
- `assumed_bounded`, lines 16–20: reserve(8) is not a hard bound and the loop inserts
  9 values. If this is a constrained path, define rejection/exhaustion and measure
  allocations; do not infer zero allocation from a reserve call.

These are compile-clean semantic defects under the stated intended contracts.
Source review identifies them; a syntax check does not prove ownership or capacity.
No TSan, Windows, benchmark, GPU or NGEN result is inferred. A future customized-project
setup must preserve existing presets/style/profiles rather than copy these fixture defaults.
