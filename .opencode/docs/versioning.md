# Versioning & Changelog

## Semantic Versioning

This project follows [Semantic Versioning 2.0.0](https://semver.org/).

Given `MAJOR.MINOR.PATCH`:

- **MINOR** — new, backward-compatible functionality (`feat:`) and, before
  1.0.0, breaking changes (`feat!:` or a `BREAKING CHANGE:` footer on any
  commit type).
- **MAJOR** — breaking changes once the project is at 1.0.0 or later.
- **PATCH** — backward-compatible bug fixes (`fix:` or `patch:`).

`cliff.toml` is the executable bump policy: `features_always_bump_minor` makes
`feat:` bump MINOR even pre-1.0, `breaking_always_bump_major = false` makes
breaking changes bump MINOR while major is 0 (and MAJOR at 1.0.0+), and
`custom_patch_increment_regex = "^patch"` makes `patch:` bump PATCH like
`fix:`. Do not hand-compute bumps.

How the next version is proposed depends on whether a prior release tag
exists:

- **Tagged repository** — `/release` applies the `cliff.toml` policy with
  `git cliff --bumped-version` and strips at most one leading `v`. If that
  produces no valid proposal despite releasable commits, the release stops —
  there is no manual bump fallback.
- **Tagless repository (first release)** — git-cliff cannot compute an
  initial version without a prior `v[0-9]*` tag, so the human supplies the
  initial version at the conversation level. `/release` validates it against
  the release grammar before any shell or ref use and still uses git-cliff
  for changelog generation.

Automated release identifiers follow the exact grammar
`MAJOR.MINOR.PATCH[-<prerelease>]`: an optional prerelease is allowed (for
example `1.2.0-rc.1`), but build metadata is not. Release tags add the `v`
prefix (`v1.2.0-rc.1`); release branches carry no `v` (`release/1.2.0`).

## Changelog

`CHANGELOG.md` is generated by git-cliff from Conventional Commits using
`cliff.toml` at the repo root. Do not hand-edit `CHANGELOG.md` — regenerate it
via the `/release` command.

Commits are grouped by the `cliff.toml` commit parsers:

- `🚀 Features` — `feat:`
- `🩹 Patches` — `patch:`
- `🐛 Bug Fixes` — `fix:`
- `📝 Documentation` — `docs:`
- `⚡️ Performance` — `perf:`
- `♻️ Refactor` — `refactor:`
- `⏪ Reverts` — `revert:`
- `💄 Styling` — `style:`
- `⚗️ Testing` — `test:`
- `📦 Build` — `build:`
- `👷 CI/CD` — `ci:`
- `🔮 Misc` — `chore:` (the `chore(release):` commit itself is skipped)
- `🔒️ Security` — any commit whose body mentions `security`

`chore(release):` and `ignore:` commits are excluded from the changelog.

## RCS header last-commit markers

Separate from release tags: every source file's RCS header carries a
normalized `creator@host`, date, and timezone that the pre-commit hook
refreshes to the last commit that touched the file. The header is a
last-commit marker under ADR-0041, not an immutable creation stamp;
provenance lives in git history. See the `rcs-header` skill for the exact
format.

## Release flow

The `/release` command authors the release PR:

1. Pre-flights a clean, synchronized `develop` and git-cliff 2.0+.
2. Proposes the version one question per turn — `git cliff --bumped-version`
   when a prior release tag exists, otherwise the human supplies the initial
   version in answer to a single question. Tagged releases go straight to the
   final confirmation; a tagless first release asks the separate final
   release-confirmation question in its own turn after the initial version is
   validated. One question per turn, never more.
3. Creates `release/X.Y.Z` via `new-branch.sh`.
4. Generates `CHANGELOG.md` with
   `git cliff --tag vX.Y.Z --output CHANGELOG.md` and replaces any surviving
   `kyaulabs/template` links with the repository detected by `gh repo view`.
5. Commits the changelog with a signed `chore(release): vX.Y.Z` commit and
   prints the human-run push and release-PR commands.

After the human merges the release PR into `main`, `.github/workflows/
release.yml` creates the unsigned `vX.Y.Z` tag and GitHub Release at the merge
SHA and opens the `main` → `develop` back-merge PR, which a human reviews and
merges. The tag and Release are created by CI, never by `/release` or an
agent. See `.opencode/commands/release.md`.
