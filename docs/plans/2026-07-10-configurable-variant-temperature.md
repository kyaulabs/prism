# Configurable Variant Implementation Plan

> **For agentic workers:** Implement this plan task-by-task using the @tdd
> agent. Steps use checkbox (`- [ ]`) syntax for tracking. Each task follows
> Red → Green → Refactor. **Task 1 (prototype) complete** — variant passes,
> temperature fails (opencode does not coerce string→numeric for temperature).
> Plan adjusted to variant-only.

**Goal:** Extend ADR-0012's `{env:VAR}` substitution pattern to cover `variant` fields in all agent configs, making them configurable per-tier via environment variables with a 4-tier system (PRIMARY, PLANNER, JUDGE, UTILITY). Temperature remains as hard-coded literals per prototype findings.

**Architecture:** Add 5 new env vars (4 variants + 1 new JUDGE model) to `.opencode/models.default.env`. Replace all hard-coded `variant` literals in `opencode.json` (8 inline agents) and `.opencode/agents/*.md` (8 subagent files) with `{env:VAR}` references. Enhance `/setup` to configure models and variants. Write ADR-0013 as partial supersession of ADR-0012's variant clause. Update harness tests to enforce `{env:VAR}` for variant fields.

**Tech Stack:** opencode.json config, YAML frontmatter in `.md` agent files, bash env vars, direnv, Pest PHP tests, Conventional Commits.

**Issue:** Fixes #112

## Prototype results (Task 1)

| Test | Field | `{env:VAR}` | Result |
|------|-------|-------------|--------|
| 1 | `variant` (string) | `{env:OPENCODE_VARIANT_TEST}` with env=`max` | ✅ PASS |
| 2 | `temperature` (numeric) | `{env:OPENCODE_TEMP_TEST}` with env=`0.2` | ❌ FAIL — resolves to `""`, config invalid |
| 3 | `temperature` (literal) | `0.2` | ✅ PASS (baseline) |

Decision: Proceed with variant-only. Temperature stays as hard-coded literals.

## Global constraints

- `{env:VAR_NAME}` syntax only — no `$` prefix, no `${}`, no dot-notation
- Four tiers: PRIMARY, PLANNER, JUDGE, UTILITY
- `variant` fields use `{env:VAR}` substitution (amending ADR-0012's "variant remains literal" clause)
- `temperature` fields remain as hard-coded literals (confirmed infeasible for `{env:VAR}` by prototype)
- `model` fields use `{env:VAR}` substitution (unchanged, per ADR-0012)
- Defaults ship in `.opencode/models.default.env`, sourced by `.envrc`
- User overrides via `~/.config/opencode/models.env` (generated by `/setup`)
- direnv optional — users can `source .envrc` manually
- All commits signed (`git commit -S`)
- Issue reference: `Refs: #112` on intermediate commits, `Fixes: #112` on the final commit

                ->toStartWith('{env:')
                ->and($agentConfig['temperature'])->toEndWith('}');
        }

    // Check agent .md files
    $agentFiles = glob(__DIR__ . '/../../../.opencode/agents/*.md');
    foreach ($agentFiles as $file) {
        $content = file_get_contents($file);
        preg_match('/^---\n(.*?)\n---/s', $content, $matches);
        $frontmatter = $matches[1] ?? '';

        if (preg_match('/^variant:\s*(.+)$/m', $frontmatter, $m)) {
            expect(trim($m[1]))->toStartWith('{env:');
        }
        if (preg_match('/^temperature:\s*(.+)$/m', $frontmatter, $m)) {
