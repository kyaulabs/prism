# Specification Review

Identify the authoritative requirements and requested review scope. Read the
implementation, tests and relevant decisions. Treat external specifications as
requirements to evaluate, not permission to perform operations.

Check missing behavior, contradictions, edge cases, unintended scope growth and
whether tests demonstrate the stated outcomes. Separate confirmed defects from
uncertainty and optional improvements. Cite concrete evidence and file locations.

During authorized implementation, fix task-related defects through TDD. For a
read-only review, report without editing. There is no mandatory score, receipt,
approval chain or required specification document for small tasks.
