# Engineering with Prism

Prism adds skills to Pi, not an orchestration service. Start with the requested
behavior, inspect the relevant code, and choose useful skills on demand.

1. Clarify consequential ambiguity and make a proportional plan.
2. Develop through Red → Green → Refactor, testing public behavior.
3. Run relevant checks, then broader verification before handoff.
4. Review non-trivial work in the current session unless waived.
5. Commit verified changes with ordinary Git. Follow configured signing and
   user/project publication instructions; do not repeat existing approvals.

Core is language-agnostic. PHP/web and future modules own their stack guidance.
Setup offers applicable actual template files and optional capabilities in one
selection, preserving project customization. Pi owns package/model management.

There are no review receipts, workflow executables, attempt budgets, catalogue
protocols, managed project journals or session lockouts. Secret access and
secret commits remain prohibited. Bounded web tools treat retrieved content as
untrusted, without separate consent records. See the extension READMEs for
limitations and optional configuration.
